# Optional RVC voice conversion

PocketPal includes an optional offline-first RVC foundation for speech-to-speech conversion and post-processing of audio generated by another TTS system. RVC is an **any-to-one** model: the target voice is encoded in a per-voice `net_g` graph. A reference WAV file by itself is not a standard RVC target model.

The feature is disabled by default and heavyweight weights are never bundled in the APK. Users may import a complete local bundle or select a curated metadata entry when the artifact is available for download. Installation validates the manifest, relative paths, byte limits, SHA-256 values, model roles, sample rates, tensor dimensions, and license/source metadata. A `.pth` checkpoint is not executable on Android; it must be converted to a validated ONNX artifact on a trusted desktop workflow before import. Archive extraction must reject absolute paths and path traversal, and downloaded code is never executed.

## Runtime architecture

The normal RVC audio path remains the JavaScript/ONNX Runtime adapter, which sequences 16 kHz ContentVec/HuBERT features, coarse/fine F0, and the per-voice `net_g` graph before writing a validated WAV. The Android `NativeRvcRuntime` bridge now also exposes a **real C++ ONNX Runtime execution path**. Its native `convert` method accepts a local `.onnx` file inside the selected model root, opens an `Ort::Session` with the CPU provider, creates typed inputs from the graph signature, runs the graph, and validates that the first output is a non-empty finite `float32` tensor. It returns output metadata and a checksum summary rather than copying a large waveform through the React Native bridge.

This native bridge is intentionally a tensor proof and safe graph-validation boundary, not yet the complete native audio product. It does not claim to perform ContentVec/HuBERT feature extraction, neural pitch extraction, chunked AudioTrack playback, cancellation, or end-to-end PCM-to-PCM conversion. Native streaming remains disabled until those pieces have physical-device latency, memory, cancellation, and audio-quality coverage. The JavaScript adapter remains the selected production audio path and does not silently play unconverted audio.

The native proof uses the same exported deterministic RVC `net_g` contract used by the supplied Peter Griffin artifact: `phone` is `[1, frames, 768]` float32, `phone_lengths` is `[1]` int64, `pitch` is `[1, frames]` int64, `pitchf` is `[1, frames]` float32, and `ds` is `[1]` int64. The exported deterministic wrapper uses the posterior mean path (`z_p = m_p * x_mask`) rather than stochastic `rnd`; this makes native smoke output reproducible, while a production quality conversion still needs the complete upstream feature and pitch pipeline.

## Verified Peter Griffin artifact

The supplied archive was inspected without executing downloaded content. It contains `PeterGriffin.pth` and an optional FAISS `.index`, but no ONNX file [1]. The checkpoint is RVC v2, F0-enabled, 48 kHz, with 768-dimensional content features. It was converted externally with the exact RVC v2 synthesizer architecture and then verified with ONNX checker, desktop CPU ONNX Runtime, and the same native C++ runner used by the Android target. The converted graph is deliberately not committed because it is approximately 110 MiB and must not be bundled into the APK.

| Artifact | SHA-256 | Size | Verification |
| --- | --- | ---: | --- |
| Supplied `Peter Griffin.zip` | `fc4a7bdaafe7b5a04b40c6fb5c610392b75bca1bfb9fcc166692943499142163` | 72.4 MiB | Archive list and checkpoint metadata inspected |
| Converted `PeterGriffin_net_g.onnx` | `fe57096644f22dacdae41d22091465e53cd3ec8230800032a39254149b8e4832` | 115,343,173 bytes | ONNX checker, desktop ORT, native C++ smoke |

For the 20-frame deterministic parity sample, the converted graph returned `[1, 1, 9600]` float32 output, all finite and nonzero. Desktop ORT versus PyTorch export had a maximum absolute difference of `0.01689`, within the documented `2e-2` float32 export tolerance. The supplied `.index` is optional and is not loaded by the current runtime; `indexRate` remains hard-coded to `0` by the execution plan.

Users must have permission to use and distribute any imported voice model. The app does not infer or grant a license from a Hugging Face page, and model metadata should retain the publisher’s license, revision, source URL, and checksum.

## Mobile defaults and warnings

| Setting | Default | Reason |
| --- | --- | --- |
| Execution mode | Offline | Network access is not required after model installation. |
| Precision | FP32 | INT8 is opt-in and must be validated per artifact. |
| Pitch extractor | DIO | Avoids loading another large neural model on limited devices. |
| Index rate | 0 | Avoids loading `.index` vector databases into mobile memory. |
| Chunk size | 2.5 seconds | Keeps streaming memory bounded when the future native path is enabled. |
| Queue depth | 2 chunks | Prevents unbounded audio-memory growth. |

The UI should warn that RVC can consume substantial storage and RAM, increase battery use, and add latency. On limited-memory devices it recommends INT8 base models, DIO/PM, index bypass, offline conversion, shorter clips, and FP32 only when the artifact budget allows it. RMVPE and FCPE are available only when the selected bundle and device budget support them. These are conservative warnings, not guarantees of real-time performance.

## TTS post-processing and model import

When a validated target model is selected, the RVC card can enable post-processing for a completed PCM16 WAV from the existing TTS engine. The TTS engine remains unchanged, and the RVC service writes a converted WAV through the validated runtime. Streaming TTS-to-RVC is not enabled by default. Model import is local-first and multi-file; a valid manifest must identify ContentVec/HuBERT, `net_g`, and any declared pitch model. The index file may be present for provenance but is ignored unless a future memory-bounded index adapter is explicitly validated.

## Contributor gates

The deterministic fixture is generated by `tools/rvc_native_fixture/generate_fixture.py`. The shared native runner is in `android/app/src/main/jni/src/rvc_onnx_runner.cpp`, and the standalone executable in `tools/rvc_native_fixture/native_smoke_main.cpp` exercises the same C++ code used by Android. Before pushing a change, run the JavaScript checks and the native smoke where the local toolchain is available:

```bash
yarn rvc:preflight
yarn rvc:smoke
yarn typecheck
yarn lint
yarn jest src/services/rvc --runInBand --coverage=false

# Host-native equivalent; CI downloads the pinned ORT 1.24.3 package.
python3 tools/rvc_native_fixture/generate_fixture.py
# Compile rvc_native_smoke with ORT 1.24.3 include/lib paths, then run:
./rvc_native_smoke tools/rvc_native_fixture/rvc_native_fixture.onnx
```

GitHub Actions runs the JavaScript gate, the host C++ compile-and-execute smoke, and the Android `prodDebug` build. The Android Gradle task extracts the pinned ONNX Runtime 1.24.3 AAR headers and ABI library into the app-controlled build directory, links `libonnxruntime.so` into the native `appmodules` target, and uses `pickFirst` only for the identical shared-library packaging collision with the React Native module [2]. The workflow also fails if ONNX, PTH, PT, or index weights are bundled into the APK. The Android build requires Node.js 22.21.0 or newer, JDK 17, Android SDK 36, NDK 27.3.13750724, and CMake 3.22.1.
