# Optional RVC voice conversion

MobiGPT includes an optional RVC foundation for speech-to-speech conversion and post-processing of audio generated by another TTS system. RVC is an **any-to-one** model: the target voice is encoded in a per-voice `net_g` ONNX model. A reference WAV file by itself is not a standard RVC target model.

The feature is disabled by default and does not bundle model weights. Enable it from the Voices and Speech setup surface, then import a complete model bundle. The bundle must contain `manifest.json`, a ContentVec/HuBERT ONNX file, a per-voice `net_g` ONNX file, and a neural pitch model when the manifest declares RMVPE or FCPE. The importer rejects `.pth` files, unsafe paths, invalid manifests, incomplete bundles, and hash mismatches.

## Mobile defaults

| Setting         | Default     | Reason                                                                             |
| --------------- | ----------- | ---------------------------------------------------------------------------------- |
| Execution mode  | Offline     | Streaming requires the experimental native backend and physical-device validation. |
| Precision       | FP32        | INT8 is opt-in and must be validated per artifact.                                 |
| Pitch extractor | DIO         | Avoids loading another large neural model on limited devices.                      |
| Index rate      | 0           | Avoids loading `.index` vector databases into mobile memory.                       |
| Chunk size      | 2.5 seconds | Native streaming uses bounded 2–3 second chunks when enabled.                      |
| Queue depth     | 2 chunks    | Prevents unbounded audio-memory growth.                                            |

On limited-memory devices, the UI recommends INT8 base models, DIO/PM, index off, and offline conversion. RMVPE and FCPE are available only when the selected bundle and device budget support them. The app reports storage/RAM warnings but does not claim that any single heuristic guarantees real-time performance.

## TTS post-processing

When a validated target model is selected, the RVC card can enable TTS post-processing. The existing TTS engine remains unchanged; the RVC service consumes a completed PCM16 WAV and writes a converted WAV through the same validated runtime. Streaming TTS-to-RVC requires the experimental native backend and is not enabled by default.

## Native streaming status

The Android build includes the optional `NativeRvcRuntime` capability bridge and shared bounded queue/crossfade primitives. The bridge currently reports streaming as unavailable until the full mobile ONNX Runtime C++ pipeline has passed graph, memory, latency, AudioTrack, cancellation, and physical-device tests. JavaScript therefore falls back to the offline adapter rather than silently playing unconverted audio.

## Contributor gate

Before pushing a change, run:

```bash
yarn rvc:preflight
yarn rvc:smoke
yarn typecheck
yarn lint
yarn jest src/services/rvc --runInBand --coverage=false
```

The repository requires Node.js 22.21.0 or newer, JDK 17, Android SDK 36, NDK 27.3.13750724, and CMake 3.22.1 for the Android build. GitHub Actions runs the same checks and a prod debug APK build; it also fails if ONNX, PTH, PT, or index weights are bundled into the APK.
